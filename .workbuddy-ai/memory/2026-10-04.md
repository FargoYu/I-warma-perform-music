## 新增编辑器插件：Auto Reload Scenes（addons/auto_reload_scenes/）

**动机**：用户用 AI agent 直接改磁盘上的 .tscn 后，Godot 编辑器不会自动刷新已打开的场景，
必须手动"双击进去 → Ctrl+S"才生效。

**实现**：EditorPlugin（@tool），每 0.5s 轮询 res:// 下 .tscn/.tres 的 mtime。
- 场景已打开 → `EditorInterface.reload_scene_from_path(path)` 自动重载
- .tres 被改 → `EditorResourceFilesystem.scan()` 重扫
- `is_playing_scene()` 时跳过，不打断运行中的游戏

**关键 API（Godot 4.7 实测）**：
- `EditorInterface.get_open_scenes()` / `reload_scene_from_path()` / `get_edited_scene_root()`
- `get_editor_toaster().push_toast(msg, EditorToaster.SEVERITY_INFO)`
- `FileAccess.get_modified_time(path)`（静态，返回 Unix 秒）
- ⚠️ 不存在 `PROPERTY_HINT_BOOL`（bool 用 `PROPERTY_HINT_NONE`）
- ⚠️ 不存在 `reload_scene_from_disk`，正确名是 `reload_scene_from_path`

**设置项**（`auto_reload_scenes/*`，运行时代码注册，不写死 project.godot）：
enabled / poll_interval / auto_reload_open_scenes / auto_reload_modified_resources /
notify_on_reload / guard_unsaved(默认关，近似脏检测) / watch_extensions

**启用**：project.godot 新增 `[editor_plugins] enabled=PackedStringArray("res://addons/auto_reload_scenes/plugin.cfg")`

**验证**：写临时测试插件 → 打开场景 → 磁盘改 .tscn → 插件日志确认自动重载成功，编辑器未崩溃。
测试文件已清理，door.tscn/block.tscn 已 git 恢复。

## Bug 修复：叠放长颈鹿被垂直支撑误判为侧墙，无法被音乐子弹推动

**现象**：一个长颈鹿踩在另一个（或多个）长颈鹿头上，或上方长颈鹿踩在两个下方长颈鹿上时，音乐子弹要求水平移动后可能被错误清零，表现为卡住。

**根因**（`objects/giraffe.gd`）：水平扫描时，垂直堆叠里的接触体仍在 GIRAFFE_LAYER 内；如果只按普通碰撞处理，骑乘者或支撑者会被当成侧墙。旧逻辑只处理“踩在自己头上的骑乘者”，且命名/判定容易遗漏“自己脚下的支撑者”这一反向情况。

**修复**：改为 `_vertical_stack_contacts()`，水平扫描前临时忽略同一垂直堆叠中的长颈鹿：
- 上方骑乘者：`self.top` 与 `other.bottom` 贴合；
- 下方支撑者：`self.bottom` 与 `other.top` 贴合；
- 两者都要求 8px 宽身体存在真实横向重叠（`abs(dx) < 8.0`），因此真正同层侧面邻居仍会阻挡。

**验证**（headless SceneTree 脚本，已清理）：
- 下方支撑者可从骑乘者下面向右滑出；
- 上方骑乘者可在两个支撑者上向右滑动；
- 真正同层侧面接触仍阻挡，且不会推走旁边那只；
- 失去支撑后仍正常下落；
- `objects/giraffe.gd` 语法检查通过，整个项目 headless 启动 200 帧无 error/warning。

**README 同步**：长颈鹿物理规则章节新增堆叠水平移动说明。

## 【重做】灭火器发光标识：改用纯 Godot CPUParticles2D（废弃 Python 方案）

**用户反馈**（重要偏好）："不要弄到外地的 py 文件里面！godot 又不是没有这种渲染的东西。
把所有东西放到 Inspector 里作为修改。" —— **用户强烈反对为视觉效果引入外部脚本/生成资源，
要求用 Godot 内置节点 + 全部参数暴露到 Inspector。**

**已删除**（Python 方案的全部产物）：
- `tools/generate_extinguisher_glow.py`（含 tools/ 目录）
- `Assets/Sprites/extinguisher_glow.png` + `.import`
- `objects/extinguisher_glow_frames.tres`（SpriteFrames 序列帧）

**新方案**（纯 Godot，无任何外部资源）：
- `objects/extinguisher_pickup.tscn`：根节点下新增 `Sparks`（**CPUParticles2D**）节点。
  关键参数：`emission_shape = 6`（EMISSION_SHAPE_RING）、`emission_ring_radius = emission_ring_inner_radius`、
  `gravity = (0,0)`（⚠️必须清零，默认 (0,980) 会让粒子下坠）、`local_coords = true`、
  `amount = 28`、`lifetime = 1.0`、`randomness = 0`、`scale_amount = 1`。
- `objects/extinguisher_pickup.gd`：14 个 `@export` 参数，分 3 组（Glow Color / Sparks / Sprite Pulse），
  全部在 Inspector 可调。setter 里调用 `_sync_*()` 实时应用到粒子节点。

**Inspector 暴露的参数**：
- Glow Color: `glow_color`
- Sparks: `sparks_enabled`, `spark_amount`(1-128), `spark_radius`(1-32), `spark_size`(0.5-4),
  `spark_lifetime`(0.1-20), `spark_drift_speed`(0-40), `spark_randomness`(0-1),
  `spark_blink_speed`(0-8), `spark_blink_min_alpha`(0-1)
- Sprite Pulse: `pulse_enabled`, `pulse_speed`(0-8), `pulse_min_brightness`(0-1), `pulse_max_brightness`(0-3)

**实现要点**：
- 环的闪烁：`_process` 里用 sin 波形调制 `_sparks.color.a`（`spark_blink_min_alpha`..1）。
- 精灵脉冲：调制 `Sprite2D.modulate` 亮度，混入 35% glow_color 色调。
- `spark_drift_speed = 0` 时粒子钉在环上，环保持完整；>0 则向外飘散。

**关键教训（CPUParticles2D）**：
- `EMISSION_SHAPE_RING = 6`（hint: Point,Sphere,Sphere Surface,Rectangle,Points,Directed Points,Ring）
- Ring 形状的内外半径相等 = 零宽度圆环；`amount` 决定同屏可见粒子数；
  `lifetime` 太长 + `amount` 太少会导致环"填不满"看起来稀疏——用 amount≈28/lifetime≈1.0 可快速铺满。
- **验证方法复用**：SubViewport(24x24) + 背景 ColorRect + 实例化场景，
  在多个帧号抓 `get_texture().get_image()`，最近邻放大拼图，可直观对比闪烁效果。

**验证**：重新导入无报错；main/roomX/Standard/room4/room5/roomp 六场景 headless 40 帧全部 OK。
